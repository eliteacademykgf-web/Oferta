# Модуль оферты — Elite Academy KG

Отдельный сервис для подписания клиентом **оферты о бронировании** (первый транш) с формированием
PDF-протокола акцепта. Работает автономно, потом подключается к серверу `eliteacademy.kg`.

## Зачем

Проблема: между первым траншем (бронь) и вторым (договор) клиент «отваливается» и требует деньги назад.
Модуль закрывает это до оплаты: клиент **не получит реквизиты**, пока не прочитает и не подпишет оферту,
где отдельными отметками зафиксировано, что он понял смысл брони, её невозвратность и срок.

Сценарий:

1. Менеджер в кабинете создаёт персональную ссылку и копирует готовый текст для WhatsApp.
2. Клиент открывает ссылку с телефона, заполняет анкету, читает 14 разделов оферты и ставит 9 отметок
   (каждая отметка открывается только после того, как раздел дочитан до конца — фиксируется время каждой).
3. Клиент расписывается пальцем и нажимает «Подписать оферту».
4. Сразу формируется PDF-протокол: полный текст оферты, данные клиента, все отметки со временем,
   подпись, IP, устройство и SHA-256 хеш документа. Клиент скачивает и присылает его менеджеру.
5. Только после этого менеджер отправляет реквизиты. Оплату он отмечает в кабинете — модуль считает
   дату окончания брони и показывает, сколько дней осталось до второго транша.

## Запуск

```bash
cd ~/Documents/elite-offer && npm install && cp .env.example .env && npm start
```

Кабинет менеджера: <http://localhost:4010/manager.html> (вход — `ADMIN_TOKEN` из `.env`).

Сквозной тест (создание → подпись → PDF → дедлайн):

```bash
cd ~/Documents/elite-offer && npm test
```

## ЧТО ОБЯЗАТЕЛЬНО ЗАПОЛНИТЬ ПЕРЕД БОЕМ

1. В `.env` — реквизиты компании (`COMPANY_LEGAL_NAME`, `COMPANY_INN`, `COMPANY_ADDRESS`,
   `COMPANY_PHONE`, `COMPANY_BANK`). Сейчас там заглушки `__ИНН__` и они попадут в PDF.
2. `ADMIN_TOKEN` — длинный случайный пароль, а не `change-me-please`.
3. Суммы и сроки в блоке `DEFAULT_*`, если отличаются от 10 000 сом / 50 000–100 000 сом / 14 дней / $200.
4. **Показать текст юристу.** Ключевой пункт 6 (невозвратность) построен на конструкции «бронирование —
   самостоятельная услуга, оказанная в момент оплаты», а не «невозвратная предоплата за обучение» —
   это сильнее с точки зрения защиты прав потребителей КР, но конструкцию должен подтвердить юрист.
   Также стоит дописать точные ссылки на статьи ГК КР — в тексте они намеренно не проставлены.

## Структура

```
server.js                 — HTTP API и раздача страниц
src/config.js             — настройки из .env (реквизиты, суммы, сроки)
src/offer-text.js         — ТЕКСТ ОФЕРТЫ (единый источник для страницы, PDF и хеша)
src/pdf.js                — генерация PDF-протокола (pdfkit + DejaVu Sans)
src/store.js              — хранилище (JSON-файл; заменяется на БД без правок остального кода)
public/offer.html + assets/offer.js|css   — страница клиента
public/manager.html + assets/manager.js   — кабинет менеджера
assets/fonts/             — DejaVu Sans (кириллица в PDF)
test/smoke.js             — сквозной тест
data/                     — подписи и PDF (в git не попадает, нужен бэкап!)
```

### Правка текста оферты

Только `src/offer-text.js`. При любом изменении смысла поднимите `OFFER_VERSION` и `OFFER_VERSION_DATE`:
уже подписанные протоколы ссылаются на свою редакцию, задним числом текст меняться не должен.

## API

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| POST | `/api/admin/offers` | менеджер | создать ссылку (`x-admin-token`) |
| GET | `/api/admin/offers` | менеджер | список со статусами и сроками |
| POST | `/api/admin/offers/:id/paid` | менеджер | отметить первый транш → дедлайн брони |
| POST | `/api/admin/offers/:id/cancel` | менеджер | отменить неподписанную ссылку |
| GET | `/api/offers/:token` | клиент | текст оферты и условия сделки |
| POST | `/api/offers/:token/sign` | клиент | подписать (валидация всех отметок) |
| GET | `/o/:token` | клиент | страница подписания |
| GET | `/o/:token/pdf` | оба | PDF-протокол (`?inline=1` — открыть в браузере) |

## Как это защищает компанию

- Отметка открывается только после прокрутки раздела — в PDF видно время каждой отметки,
  поэтому «я не читал» и «мне не объяснили» не работают.
- ФИО, номер паспорта и телефон вводит сам клиент; ФИО дублируется в поле подписи.
- Фиксируются IP, устройство, время открытия ссылки и время на странице.
- SHA-256 считается от текста оферты + данных акцепта: подмена текста задним числом видна.
- Повторно подписать ссылку нельзя, ссылка персональная и одноразовая.
- Отдельный акт об оказании услуги бронирования не нужен — п. 2.3 оферты закрывает это,
  а протокол акцепта служит подтверждением.

## Режим «Документ Word»

Кроме встроенной оферты о бронировании, менеджер может загрузить любой документ `.docx`
(вкладка «Документ Word» в кабинете):

1. Файл конвертируется в PDF через LibreOffice (`soffice --headless`) — так сохраняются таблицы,
   шрифты, отступы, нумерация, картинки и печати. Исходник не меняется; SHA-256 `.docx` и его
   PDF-версии фиксируются при загрузке.
2. Клиент открывает ссылку и читает документ по одной странице. Отметка «Я ознакомился(ась)
   с содержанием данной страницы» становится доступна после отрисовки страницы; сервер принимает
   отметки только по порядку и только после открытия страницы. Отметки сохраняются сразу —
   после перезагрузки клиент продолжает с того же места.
3. После последней страницы — ФИО, подпись пальцем/мышью, итоговое подтверждение.
4. Итоговый PDF = все страницы исходника + лист подписания (время подтверждения каждой страницы,
   подпись, IP, устройство, хеши). Внизу каждой страницы — номер документа и хеш подписания.
5. В кабинете — этап (готов к отправке → отправлен → просматривает → ожидает подписания →
   подписан), журнал действий со временем и IP, предпросмотр, скачивание оригинала и итогового PDF.

Файлы документа лежат в `DATA_DIR/docs/<id>/` (`source.docx`, `source.pdf`) — их тоже нужно бэкапить.

**LibreOffice на сервере** (уже установлен на дроплете вместе со swap 2 ГБ):

```bash
apt-get install -y --no-install-recommends libreoffice-writer-nogui fonts-dejavu fonts-liberation fonts-liberation2 fonts-crosextra-carlito fonts-crosextra-caladea
```

Шрифты Carlito/Caladea/Liberation метрически совпадают с Calibri/Cambria/Times/Arial — без них
вёрстка Word-документа «поедет». Конвертации выполняются строго по одной (память).

**Локально без LibreOffice** — через Docker-образ с ним (Dockerfile: `ubuntu:22.04` + те же пакеты):

```bash
SOFFICE_DOCKER_IMAGE=elite-offer-soffice:dev npm test
```

`npm test` пропускает сценарий с `.docx`, если не найден ни `soffice`, ни `SOFFICE_DOCKER_IMAGE`.

(nginx + systemd-юнит `elite-offer`, конфиги — в `deploy/`).

`SSH_PRIVATE_KEY` — в Settings → Secrets репозитория.

## Деплой на Railway

Модуль уже подготовлен: порт берётся из `PORT`, домен — из `RAILWAY_PUBLIC_DOMAIN`,
настройки читаются из переменных окружения, healthcheck — `/healthz` (`railway.json`).

**Главное: подключить Volume.** Файловая система контейнера на Railway одноразовая — при каждом
редеплое она обнуляется. Без диска все подписанные оферты и PDF пропадут.

1. Загрузить код:
   ```bash
   npm i -g @railway/cli && railway login && cd ~/Documents/elite-offer && railway init && railway up
   ```
   (или запушить папку в приватный репозиторий GitHub и в Railway выбрать «Deploy from GitHub repo»).
2. В сервисе → **Variables** задать:
   `ADMIN_TOKEN` (длинный случайный), `DATA_DIR=/data`, `COMPANY_LEGAL_NAME`, `COMPANY_INN`,
   `COMPANY_ADDRESS`, `COMPANY_PHONE`, `COMPANY_BANK`, при необходимости `DEFAULT_*`.
   `PORT` и домен Railway подставляет сам.
3. Сервис → **Data** → **Add Volume**, mount path `/data` (совпадает с `DATA_DIR`).
4. Сервис → **Settings** → **Networking** → **Generate Domain**. Ссылки клиентам будут вида
   `https://<домен>/o/<токен>`. Свой домен (`offer.eliteacademy.kg`) добавляется там же + CNAME в DNS.
5. Проверить: `https://<домен>/healthz` → `{"ok":true}`, затем зайти в `/manager.html`.

Ограничения, о которых нужно знать:

- Бэкап: Railway не делает автоматических копий Volume. Раз в неделю скачивать `/data/offers.json`
  (`railway run cat /data/offers.json > backup.json`) — там все подписи. PDF восстанавливаются из него сами.
- Хранилище — JSON-файл, рассчитан на один экземпляр сервиса. Не включать несколько реплик.
- Альтернатива без оплаты Railway: тот же модуль ставится на уже работающий дроплет
  (см. следующий раздел) — там nginx и домен уже есть.

## Подключение к своему серверу (альтернатива Railway)

На дроплете `159.89.38.67` уже есть nginx и работающий `api.eliteacademy.kg`. План:

1. `rsync` папки в `/home/elite-offer`, `npm ci --omit=dev`, systemd-юнит `elite-offer.service` на порт 4010.
2. В nginx — новый location (например `offer.eliteacademy.kg` или `/offer/` на основном домене)
   с `proxy_pass http://127.0.0.1:4010` и передачей `X-Forwarded-For` (нужен для фиксации IP клиента).
3. `PUBLIC_BASE_URL` = боевой адрес, иначе ссылки в WhatsApp будут вести на localhost.
4. Бэкап `data/` (там подписи и PDF) — минимум ежедневный.
5. Опционально: автоотправка PDF менеджеру в WhatsApp через API вместо ручной пересылки клиентом.
